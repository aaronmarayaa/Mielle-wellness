# Website email through FormSubmit

Careers applications use FormSubmit's [documented native file upload](https://formsubmit.co/documentation): a browser POST to `https://formsubmit.co/miellewellness@gmail.com` with `enctype="multipart/form-data"` and a file input named `attachment`. PDF, DOC and DOCX resumes up to 10 MB are accepted. The selected phone number is formatted with its international calling code. The application message is optional; names, email, phone and resume remain required. Careers no longer uses the AJAX endpoint, which sent the text in the user's test without delivering the resume.

The shared Home/inner-page contact form still posts to `https://formsubmit.co/ajax/miellewellness@gmail.com`. Its message is required. Both forms use the visitor's `email` for Reply-To, **Mielle Wellness** subjects and FormSubmit's `table` template.

No API key, Gmail password or Node email backend is needed. Run `npm run dev` as usual. Static website hosting also works with this integration.

The recipient was changed from the personal test inbox to **miellewellness@gmail.com** at the user's request. FormSubmit requires activation when the recipient changes. Submit the contact form once and open the activation email in `miellewellness@gmail.com`; check Spam if needed. Click the confirmation link before testing delivery again. FormSubmit retains unconfirmed text submissions, but not uploaded files, so submit the Careers form again with the resume after activation. Confirmation can be required for each form URL. See [FormSubmit setup](https://formsubmit.co/) and [activation/file retention](https://formsubmit.co/help).

Careers navigates to FormSubmit to complete the submission, including its CAPTCHA if requested. The `_next` URL returns to this site's `/careers?application=submitted#application` after acceptance; the fresh form clears the inputs, resume and filename, defaults the phone country to Canada and displays confirmation. The temporary query marker is then removed. Only Submit is disabled while navigating, so disabled fields cannot drop the file from the native POST. If FormSubmit asks for activation or shows an error, complete its instructions or use browser Back to retry; the site does not show success prematurely. Browsers may require selecting the resume again after navigating back.

Contact inputs clear only after a successful JSON response. Failed contact requests, including activation-required responses, retain entered details for retry. A return page or successful response is not proof that an email arrived. Confirm actual delivery in Gmail, including the resume attachment.

FormSubmit's [documented customization](https://formsubmit.co/documentation) supports the subject and three built-in templates. It does not document form settings for a custom From name, sender avatar or logo embedded in the email. **Mielle Wellness** in the subject does not rename the sender. To control the sender identity and a custom HTML logo, use an email provider with those features and a verified sending address.

Browser checks intercept the native Careers POST and verify the recipient, multipart encoding, Mielle subject, reply email, international phone, UTF-8 filenames and exact PDF/DOCX bytes. They simulate the provider's accepted redirect and activation page, verify an empty application message can submit, and check the cleared form on return. Contact checks cover required messages, acceptance, activation, rejection and network failure. These checks send no real emails and do not verify FormSubmit's downstream attachment delivery.
